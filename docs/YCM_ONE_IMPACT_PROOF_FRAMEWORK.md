# YCM One Impact Proof Framework

## Purpose

YCM should be able to demonstrate measurable outcomes at state, district and block level without exposing personal information.

The impact record is separate from the operational case record. A completed service is an output; a verified improvement or beneficiary outcome is an outcome.

## Education / improvement example

For a student:

1. capture consent;
2. record baseline assessment and date;
3. record the YCM intervention;
4. record follow-up assessment and date;
5. attach evidence reference;
6. verify the evidence;
7. calculate the change;
8. aggregate only de-identified statistics at block/district/state level.

Example:

Baseline score: 43
Follow-up score: 65
Improvement: +22 percentage points

The system must retain the dates, assessment methodology and evidence reference. It must not claim that YCM caused the improvement unless the evidence and methodology support that attribution.

## Geography

Every impact record should carry:

- state
- district
- block
- optional village
- service / intervention
- outcome type

This allows a CEO / authorised government-facing report to answer:

- how many people were served?
- how many cases were completed?
- how many verified outcomes occurred?
- which blocks were covered?
- what changed after intervention?
- what evidence supports the reported outcome?

## Evidence

Evidence should be classified, not stored as an uncontrolled text claim.

Examples:

- baseline assessment
- follow-up assessment
- official document
- institution confirmation
- application receipt
- benefit confirmation
- employment confirmation
- field visit
- third-party verification
- consent record

Raw personal documents should remain access-controlled. Public or government-facing reports should use aggregated / de-identified data unless lawful disclosure is explicitly required and authorised.

## Government-facing evidence packet

A report packet should contain:

1. reporting period;
2. geography;
3. methodology version;
4. population / number of families or beneficiaries covered;
5. outputs;
6. verified outcomes;
7. baseline vs follow-up measures where applicable;
8. evidence counts;
9. limitations / missing data;
10. consent and privacy statement;
11. audit generation timestamp.

## Dashboard levels

CEO:
- all states
- districts
- blocks
- outcome trends
- evidence verification rate
- intervention mix

District:
- district and blocks under scope
- outcome trends
- pending verification
- service delivery

Block:
- local coverage
- beneficiaries served
- interventions
- verified outcomes
- pending evidence

## Important measurement rule

YCM must distinguish:

- Output: “application completed”
- Outcome: “benefit / placement / enrolment / measurable improvement confirmed”
- Impact: “sustained change supported by an appropriate evaluation design”

This distinction prevents marketing claims from being presented as government evidence.

## Reference model

NITI Aayog's work on Aspirational Districts / Aspirational Blocks uses block-level KPIs and data-driven monitoring, while its education case studies describe dashboards aggregating data across state, district, block and school levels. YCM's evidence model follows the same general principle of measurable, geographically aggregated outcome monitoring, while remaining specific to YCM's services.
